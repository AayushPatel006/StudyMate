# Development Notes — StudyMate Midterm (Phase 1)

## Scope split (from the proposal)

The proposal's milestones were M1 Foundation → M2 Core planner (non-AI) → M3 AI planning + replanning → M4 testing. The midterm MVP covers M1, M2 and the **generation** half of M3 (AI planning, prioritisation, session breakdown, validation, fallback). The **replanning** half of M3 (US-2, UC-6, FR-8/9/12) is deliberately left for the final presentation and documented in `FUTURE_DEVELOPMENT.md`.

| User story | Phase 1 coverage |
|---|---|
| US-1 Create a realistic study plan | Complete (Cucumber: *Plan fits before the deadline*). |
| US-2 Update the plan as I make progress | Not in Phase 1 (task status only; plan marked stale). |
| US-3 Stay in control | Partial: move/edit/delete sessions with validation. Preserving edits across re-plans is Phase 2. |

## Gemini free-tier choice (verified Nov 2026)

The official pricing page (https://ai.google.dev/gemini-api/docs/pricing) listed these text models as **Free of charge** on the free tier: `gemini-3.5-flash`, `gemini-3.1-flash-lite`, `gemini-3-flash-preview`, `gemini-2.5-pro`, `gemini-2.5-flash`, `gemini-2.5-flash-lite`. Paid-only examples: `gemini-3.1-pro-preview`, image models.

Default: **`gemini-2.5-flash`** — stable (non-preview), free, supports structured JSON output, good reasoning for scheduling. The model is read from `GEMINI_MODEL`, so it can be changed without code edits. Free-tier quotas vary by model and change over time; check AI Studio for current limits.

Not verified in this build environment: a live call to Gemini (no API key was available). The integration is covered by tests with a mocked client (request shape, JSON schema config, parsing, id mapping, 429/timeout/invalid-key handling). Verify a real key end-to-end once: Settings should show *Gemini connected*, the planner banner should read *Generated by Gemini*, and the assistant should answer.

## Prompting

- System instruction lists the hard rules (the validator enforces them anyway) and planning guidance (deadline → priority → size; spread work; give each session a concrete *focus*).
- Input is compact JSON: `now`, `planningDays [{date, weekday, from, to}]`, `limits`, `tasks [{id: "T1", …, due, remainingMinutes, notes}]`.
- Output schema: `{ summary, prioritizedTasks[{taskId, rank, reason}], sessions[{taskId, date, startTime, endTime, focus, explanation}] }`, requested with `responseMimeType: "application/json"` and `responseJsonSchema`.
- `temperature: 0.3` for planning, `0.6` for chat. No thinking config is set so the same code works across Flash model generations.

## Error handling matrix

| Situation | Planner | Assistant |
|---|---|---|
| No key | Fallback (`NOT_CONFIGURED`) | 503 "needs a Gemini API key" |
| 429 / RESOURCE_EXHAUSTED | Fallback (`RATE_LIMITED`) | 429 "free-tier limit reached" |
| Invalid key / 401 / 403 | Fallback (`INVALID_KEY`) | 503 with message |
| Model not found / paid-only | Fallback (`MODEL_UNAVAILABLE`) | 503 with message |
| Timeout (45 s) / network | Fallback (`TIMEOUT` / `NETWORK`) | 503 with message |
| Malformed JSON / no valid sessions | Fallback (`INVALID_RESPONSE`) | — |
| Some sessions invalid | Gemini plan, invalid ones dropped, gaps filled, `AI_ADJUSTED` note | — |

## Conventions

- Backend is ESM (`"type": "module"`), Express 5 (async errors propagate to the error handler automatically).
- Controllers throw `HttpError`; never send raw errors to clients.
- Internal Mongo queries that need operators while `sanitizeFilter` is on wrap them in `mongoose.trusted(...)`.
- UI: Tailwind v4 with theme tokens in `src/index.css` (`brand-*`, `shadow-soft`, `ai-gradient`). Shared primitives live in `components/ui/index.jsx`.
- Priority colours: High = rose, Medium = amber, Low = emerald — used consistently in badges, calendar blocks and lists.
